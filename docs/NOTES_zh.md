> 这份是"讲给自己听"的精简版。完整实验记录见 `docs/ROADMAP.md`，英文正式说明见 `README.md`。

## 0. 30 秒讲清楚这个项目

> 我做的是任务 3：让 Franka 把球投进篮子。机械臂先用微分 IK 把球从台子上抓起来，然后摆到一个"手臂伸直、往后仰 45°"的后摆姿态，
> 像甩鞭子一样让肩、肘、腕同时全速往前转，手最快能到 3.5 m/s。挥臂过程中，每一个物理步都用球当前的位置和速度预测
> "如果现在松手，球会在哪里经过篮筐口"，预测点到达篮筐中心的那一步就张开夹爪，同时让手臂刹车。
> 篮子位置随机，10 次全部投进。README 里还拆解了误差来源：最大的是"只能在整帧松手"造成的 ±4 cm，另外有两个 2~3 cm 的系统偏差。

---

## 1. 整体流程

```
抓球（IK + 状态机）→ 后摆（关节插值，慢）→ 挥臂（关节目标一次设到位，快）
   → 每帧预测落点 → 最接近目标的那帧：张开手指 + 刹车 → 等球停下，判断进没进
```

对应文件：`scripts/07_trials.py`（最终版），公共工具在 `scripts/franka_utils.py`。

## 2. 核心概念（按学习顺序）

### 2.1 仿真基础
| 概念 | 一句话 |
|---|---|
| Stage / Prim | 场景是一棵树，每个物体是一个节点，用路径表示，如 `/World/Ball` |
| 外形 / 碰撞 / 刚体 | 三件事分开设置：只有外形 = 纯视觉（绿色瞄准点）；外形 + 碰撞 = 固定障碍（台子、篮子）；再加刚体 = 会受重力、会被推动（球） |
| Articulation | 关节机器人。Franka 有 9 个自由度：7 个手臂关节 + 2 根手指（平移，每根 0~0.04 m） |
| 关节电机 = 弹簧 | 力 ∝ (目标 − 实际) − 阻尼 × 转速。它是"追目标"，不是"瞬移"。**很多现象都靠这一条解释** |
| `set_xxx` / `get_xxx` | API 成对出现；实验版 API 返回 warp 数组，要 `.numpy()` 转换 |
| 物理步长 | PhysX，dt = 1/60 s，每次 `simulation_app.update()` 前进一步 |

### 2.2 轨迹预测（练习 1）
- 连续公式：`p(t) = p0 + v0·t`，z 方向再减 `½gt²`。
- **仿真是离散的**：PhysX 用半隐式欧拉法（先更新速度，再用新速度更新位置），所以每秒会比连续公式多掉 `½·g·dt`。
  我们是从"误差随时间线性增长、斜率 8.1 cm/s"反推出来的：½ × 9.81 × (1/60) = 8.2 cm/s。
- 补偿后：`z -= ½gt² + ½g·dt·t`，预测误差从 5 cm 降到 **0.00 cm**。
- 逆问题（给定目标点和飞行时间 T 求初速度）：`v0 = (目标 − 起点)/T`，vz 再加 `½gT + ½g·dt`。
- **有一个最省力的 T**：T 太小时水平速度大，T 太大时竖直速度大，中间最小。所以 T = 0.4 和 0.6 需要的出手速度几乎一样。

### 2.3 IK：让夹爪去指定位置（练习 2）
- **雅可比矩阵 J（6×7）**：每个关节转一点点，手会怎么动。它只在当前姿态附近准确，所以**每帧重新算一次，每次只走一小步**。
- **阻尼最小二乘**：`Δq = Jᵀ(JJᵀ + λ²I)⁻¹·误差`。J 不是方阵，没法直接求逆；λ 防止手臂接近伸直（奇异姿态）时关节乱转。
- **夹爪中心 ≠ 手掌**：两指中心在 `panda_hand` 前方 0.1034 m 处，IK 的目标要先换算成手掌的位置。
- **P 控制和 I 控制**：
  - 目标 = 实际角度 + Δq → **P 控制**：稳定，但重力会留下 0.2~0.5 cm 的误差（弹簧要被拉长一点才托得住手臂）。
  - 目标 = 上一帧目标 + Δq → **I 控制**：能消掉剩余误差，但 scale = 1 时累加太快、手臂又有延迟，就会乱舞；scale = 0.05 时稳定但慢。
- 实测从 READY 到 1 cm 以内要 0.6~1.2 s，**太慢，不能用来挥臂**。

### 2.4 夹爪与状态机（练习 3）
- **夹紧力 = K × (手指目标 − 手指实际)**。手指被球挡在 0.03，目标是 0.0，这个差值就是夹紧力。
- **状态机**：动作流程是一张表（阶段名、目标、手指、最长时间、提前结束的误差），执行循环和表分开。
  不需要移动的阶段（合爪、保持）要固定等满时间，不能按误差提前结束。
- **成功判定必须和任务定义一致**：加了"放回去"以后还用"举高了没有"来判断，就会出现假阴性（明明成功了却判失败）。
  **判断成功要看物体的位置，不能只看夹爪到没到位**。

### 2.5 挥臂："甩鞭子"（04）
- 手的速度 = 各关节贡献的**向量和**；每个关节贡献的大小 = 角速度 × 力臂，方向垂直于"关节 → 手"的连线。
- 单关节实验：肩 1.57 m/s，肘 1.06，腕 0.60。加起来约 3.2，所以方向对齐后速度是够的。
- **关键发现**（从数据反推）：
  ```
  上臂 θ1 = q[1]      小臂 θ2 = q[1] − q[3]      手 θ3 = q[1] − q[3] − q[5] + π
  ```
  q[3]、q[5] 增大时，小臂和手是往**后**转的。第一次尝试三个角度都增大，结果互相抵消，只有 1.14 m/s。
- 正确做法：后摆时手臂伸直、往后仰 45°（`[0, −0.785, 0, −0.07, 0, π]`）；挥臂时 q[1]↑、q[3]↓、q[5]↓，最大速度 **3.46 m/s**。
- 手的速度方向垂直于手臂 → 手臂后仰多少度，出手仰角就是多少度。
- 肩要带动整条伸直的手臂，受**力矩上限**限制，0.45 s 才达到最高转速，所以存在"速度和角度"的取舍。
- 挥臂用**关节空间控制**：直接把目标设成最终角度，电机全速转过去。后摆则要**插值**（余弦曲线，慢起慢停），否则还没挥球就甩掉了。

### 2.6 松手（05，最关键的实验）
| 手指排列 q[6] | 刹车 | 发出指令后几帧离手 | 结果 |
|---|---|---|---|
| 2.356（前后排，在挥臂平面里） | 否 | 18~19 | 后面那根手指一直顶着球，等离手时方向已朝下 |
| 0.785（左右排） | 否 | 4~6 | 手腕比球快，从后面追上撞了球，误差 22 cm |
| **0.785** | **是** | **2** | 没有碰撞，按指令时的状态预测，落点误差只有 3.1 cm |

- 为什么刹车有效：手一减速，球就往前冲出手指之间的空隙，"发出指令"和"真正离手"几乎是同一时刻，所以指令时读到的 p 和 v 就是真实的初始状态。
- 判断有没有碰撞，看"从离手时的状态预测的误差"：自由飞行时它应该一直是 0，突然开始线性增长就说明被撞了。

### 2.7 闭环松手与瞄准（06、07）
- 每帧求"球往下落时经过篮筐口高度的位置"：令 z(t) = z_rim，得到一元二次方程，**取较大的根**（先往上经过一次，再往下落经过一次），再代入 x(t)、y(t)。判别式 < 0 表示飞不到这个高度。
- **四舍五入到最近的一帧**：预测落点每帧大约前进 10~12 cm。估算下一帧 ≈ 本帧 + (本帧 − 上一帧)，本帧已经过了两者的中点就松手。
- **瞄准**：q[0] = atan2(y, x)，整个挥臂平面转过去对准篮子；比较的是"落点在瞄准方向上的投影距离"。

## 4. 踩过的坑（面试时很好的素材）

1. **关节插值把夹紧力插没了**：从手指的实际位置开始插值，一开始"目标 = 实际"，夹紧力为 0，球就掉了。
   → 会被物体挡住的关节，目标不能从实际位置推算。
2. **关节符号相反导致速度抵消**：1.14 m/s → 推出符号关系后 3.46 m/s。
3. **"兜得太好"反而放不开**：手指前后排列时后面那根手指一直推着球。这是直觉没想到、靠实验测出来的。
4. **手臂追上已经扔出去的球**：通过"按离手时预测误差从 0 开始线性增长"定位到撞击发生在哪一帧、是哪个部位（手腕），然后用刹车解决。
5. **猜想被数据推翻**：以为侧向偏差来自手臂离开了挥臂平面，一测发现 q[0]/q[2]/q[4] 几乎不动；
   又以为是随机抖动，10 次数据显示全偏同一侧，所以是系统偏差。→ **先测，再下结论；样本太少不下结论**。

## 5. 可能被问到的问题

**Q：为什么选投篮，不选接球？**
接球要求手臂在球飞行的 0.6 s 内到位，而我实测 IK 到位就要 0.6~1.2 s，一周内风险太大。投篮可以直接用上轨迹预测的逆问题，难度适中，也更容易定量评估。

**Q：出手时机是怎么决定的？为什么不提前算好？**
每一帧都用球的实际状态做预测（闭环），所以挥臂快一点、慢一点都没关系，会自动选到合适的那一帧。如果提前算好，就得依赖挥臂轨迹每次完全一样。

**Q：为什么不在速度最快的时候松手？**
速度最快时方向已经朝下了（−32°）。松手时机由篮子的位置决定，不由速度决定。

**Q：最大的误差来源是什么？怎么改进？**
只能在整数帧上松手，落点每帧移动 10~12 cm，所以有 ±4 cm 的误差。可以把物理步长改成 1/120，误差减半；或者调整挥臂速度，让某一帧正好落在目标上。
另外两个系统偏差（多飞 2.6 cm、侧向 −2.2 cm）可以直接补偿。

**Q：10/10 可信吗？**
要说实话：这是没有噪声、完全确定的仿真，样本只有 10 次，而且最差的一次已经踩到篮筐边了。下一步应该加噪声（球的位置、篮子的位置、关节增益），跑几百次。

**Q：如果换到真实机器人上，会遇到什么问题？**
需要视觉来估计球和篮子的位置（有噪声和延迟）；真实夹爪的开合延迟和摩擦都不一样；Franka 真机有加速度和 jerk 限制，这样全速挥臂可能会触发保护；松手偏差需要重新标定。

**Q：半隐式欧拉是什么？为什么重要？**
仿真先更新速度，再用更新后的速度去更新位置。所以每一步都比连续公式多掉一点点，每秒多 ½·g·dt。
如果不补偿，飞行 0.6 s 就会差 5 cm，足够让球投不进。

**Q：你怎么调试"球被撞"这个问题的？**
对比了两种预测：从"发出指令时"的状态出发，和从"真正离手时"的状态出发。后者在自由飞行时应该一直是 0，结果在 0.45~0.50 s 之间突然开始线性增长，而且仰角反常地往上抬，说明被从下后方推了一下。
当时球离两指中心 25 cm，所以撞到球的是手腕。
